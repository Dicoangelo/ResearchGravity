## NotebookLM coverage and interpretation

The selected notebooks cover the ResearchGravity execution playbook, convergence
protocol, UCW memory research, and a research-to-experiment memory/retrieval
study. None supplied the historical BASIX Index/Broker/Rails/Vault/Governance
specification; that evidence comes from the separate private Grok recovery.
No BASIX-titled notebook was found in the catalog search. That is a search
observation, not proof that the corpus contains no other related material.

The raw memory-results source describes a frozen synthetic experiment comparing
keyword retrieval with an added reranker, including citations, abstention cases
and offline replay. It explicitly limits the result to its artificial fixture
and preserves the production baseline pending human-reviewed real-memory
questions. Notebook synthesis is therefore not used to claim general retrieval
superiority or to switch production defaults. Original sources and query results
remain private; this public source map records only scope and reusable method.

## New v1 surfaces and evidence ownership

- `basix/planner.py`: deterministic typed validation and feasibility decisions.
- `basix/store.py`: immutable content-addressed receipt persistence.
- `basix/handoff.py`: selected-decision export and readable handoff.
- `basix/researchgravity.py`: explicit-path project storage integration.
- CLI, loopback UI and MCP: access the same decision functions; their final
  acceptance belongs in the release validation record.
- `tests/test_basix_planner.py`: 80 unit cases passed during implementation on
  October 25. This is a bounded core result, not proof of live cloud operation.

No source count, historical completion badge or assistant-generated confidence
is used as evidence of product readiness. Present-day validation supersedes a
planning document's status label while retaining the original document intact.
